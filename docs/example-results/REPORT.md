## Evaluation protocol

Calendar days are split 60% / 20% / 20% into training, validation and test. Features use only earlier timestamps. The alert threshold is set using validation scores to stay within a 5.0% alert budget; the test alert rate may differ. Rule-score ties can make their threshold more conservative. Ranking precision at the budget is also included in metrics.json.

## GraphSAGE

Two layers of mean message passing over 26,327 transaction nodes and 73,433 directed temporal edges. Validation selected epoch 40 out of 40 epochs run.

Messages arrive only from earlier transactions sharing an account (at most eight neighbours within 24 hours per edge). The optimisation graph contains training nodes only. Normalisation is fitted on training features. Checkpoint selection and alert threshold use validation data; the held-out test is evaluated afterwards.
